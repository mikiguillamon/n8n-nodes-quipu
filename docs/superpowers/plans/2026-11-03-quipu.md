# Quipu Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the approved Quipu community node, all 49 documented operations covered, with guided forms and an npm-ready package.

**Architecture:** Programmatic node with a checked-in public contract projection, handcrafted form conventions, shared serializers, HTTP transport and lookup methods. Contract extraction happens at development time only. No runtime external dependency.

**Tech Stack:** TypeScript, @n8n/node-cli, n8n-workflow, Node test runner; YAML parser as a development dependency only.

**Spec:** ../specs/2026-11-03-quipu-design.md (approved by “Adelante”).

## Global Constraints

- Package `@mikiguillamon/n8n-nodes-quipu`; MIT; English interface and public docs.
- 49 public operations: credential acquisition plus 48 guided API operations.
- Fixed origin https://getquipu.com; mandatory scope ecommerce; rate limit 5 requests per 5 seconds.
- No runtime filesystem/environment access or third-party runtime dependencies.
- User authorized implementation; execute inline in the dedicated new project directory. No further design approval is needed.

## Review Focus

- Partial updates must preserve omitted versus null/false/zero/empty; test payloads explicitly.
- Lookups spanning pages must expose all choices and not manufacture server-side search; test continuations.
- Credentials must never reach arbitrary hosts or exception output; test hostile paths and error redaction.
- A mutation timeout must not create duplicate invoices through retries; test attempts and 429 behavior separately.
- Raw and simplified output must retain included resources and item linkage; test multi-input, multi-page results.
